# 《HTML5 小游戏商业化改造需求文档》—— 通用可复用模板 v1.1

> **用途**：任何休闲 HTML5 小游戏的商业化改造，都可复制本模板套用。
> 覆盖**变现 / 留存 / 数据 / 合规**四大模块，每项需求都带验收标准。
> 新项目开工前、上线前，都按本模板过一遍 → 这是你的"商业合规检查清单"。
>
> **编写**：豆包（Doubao）· 吸收 GPT 评审口径（TEST/ONLINE 双环境架构）· 2026-09-27

---

## 0. 核心原则（先读，比清单重要）

1. **商业设计必须在写代码之前定案**。广告触发场景、留存机制、埋点口径，一旦写进代码再改，成本翻倍。
2. **KPI 是需求的一部分**，不是结果。需求文档不写"广告日均曝光目标"和"次日留存目标"，WorkBuddy 就只会把功能做对，不会为结果负责。
3. **"零依赖单文件"必须为商业让步**。广告 SDK 是外部 JS，接广告=打破零依赖，这是必要妥协，不是缺陷。
4. **广告触发条件 ≠ 玩家卡死**。靠"玩家走投无路"触发广告 = 广告触发≈0。广告要挂在**日常高频动作**上。
5. **【v1.1 新增】广告必须 TEST / ONLINE 双环境 + AdService 适配层**，禁止游戏逻辑直连真实 SDK，保证 QA 可重复、平台可更换。

## 1. 商业目标与 KPI（每项目必填）

### 1.1 变现模型（选）
| 项 | 默认建议 | 说明 |
|---|---|---|
| 激励视频 | ✅ 必做 | 休闲游戏主力变现位，玩家主动换取收益 |
| 插屏 | 可选（P2） | 只在"结算→下一关"之间低频弹 |
| Banner | 可选（P2） | 收益低，可能伤体验 |
| 内购（去广告/皮肤） | 可选（P2） | 需先验证付费意愿 |

### 1.2 目标 KPI（填空，口径见右列）
| 指标 | 目标值（项目自填） | 计算口径 |
|---|---|---|
| 广告日均曝光次数 | 上线第 4 周 > 100 次 | 激励视频弹窗次数（埋点曝光事件） |
| 广告完成率 | > 60% | 完成数 ÷ 曝光数 |
| 次日留存 | > 5% | 次日活跃 ÷ 当日新增 |
| 人均广告观看 | > 1 次/DAU/日 | 完成数 ÷ DAU |
| 单局时长 | ≤ 5 分钟 | 关卡开始→通关/退出的平均时长 |

## 2. 广告接入技术方案（回答"HTML5 能不能植入广告"）

**能。HTML5 游戏植入广告 = 引入平台提供的 JS 广告 SDK + 按平台 API 调用。** 与用什么工具（Cursor、MCP、WorkBuddy）无关。

| 平台 | 接入方式 | 要点 |
|---|---|---|
| **TapTap H5 小游戏** | 开发者平台开广告 → 引入 TapTap JS SDK → 调用激励视频接口 | 支持上传 HTML 静态包；广告位需审核 |
| **抖音小游戏** | `tt.createRewardedVideoAd()` | 流量大、eCPM 高，审核严 |
| **微信小游戏** | `wx.createRewardedVideoAd()` | 用户量大但审核最严 |
| **通用 H5（自有站点）** | 聚合广告（穿山甲 / AdMob Web 等） | 不需平台入驻，但合规责任在己 |

**【v1.1 架构硬约束】必须分层**：
```
Game → AdService → TestAdProvider（TEST 环境）/ TapTapAdProvider（ONLINE 环境）
```
- TEST：点击广告 → 立即返回模拟完成 → 发测试奖励 → 不产生真实收入（QA 可重复）
- ONLINE：调真实 SDK → 完成回调才发奖励 → 加载失败/中途退出不发 → 频控 → 埋点
- 切换环境只改配置，不重写游戏逻辑；广告平台更换时不改游戏代码。

## 3. P0 需求清单（每项带验收标准，可直接发给 WorkBuddy）

### 3.1 变现（R 类）
| # | 需求 | 验收标准 |
|---|---|---|
| R1 | **激励视频 SDK 接入（TEST/ONLINE 双环境 + AdService 适配层）**，替换所有假"看广告"按钮 | 真广告可播放；看完才发奖励；TEST/ONLINE 一键切换；测试位可演示 |
| R2 | **广告场景 ≥ 2 个，且挂在日常动作上**（结算翻倍 / 失败重试 / 撤销补次 / 开局增益），禁用"卡死才弹" | 每场景触发次数有埋点；日常对局可自然触发 |
| R3 | **广告失败降级**：加载失败/超时/无填充 → 直接给奖励或跳过 | mock 断网：流程不被卡住，可继续游戏 |
| R4 | **删除/替换所有假广告、假分享按钮** | 代码审查：无"点了直接给奖励"的假按钮；分享要么真调系统/平台能力，要么移除 |
| R5 | 结算页"双倍奖励"按钮（激励视频） | 结算页出现；点击→看广告→收益×2；未看完不发放 |

### 3.2 留存（K 类）
| # | 需求 | 验收标准 |
|---|---|---|
| K1 | **本地存档**：关卡进度+道具+最高关+设置；带校验和；损坏自动重建 | 刷新/关闭重开不丢进度；篡改 localStorage 无效或自动修复 |
| K2 | **新手教学（前 3 关）**：核心规则逐步引导 | 模拟新手前 3 关可独立完成，无困惑卡住 |
| K3 | **单局时长控制 ≤ 5 分钟**：后期关卡加步数目标或砍规模 | 机器人采样：第 30 关平均时长达标 |
| K4 | **结算星级** + 关卡列表星标 | 结算页显示星级；选关页显示历史星级 |
| K5 | **每日挑战 + 连续签到**（第 1/3/7 天奖励递增） | 每日有独立关卡；签到进度本地记录 |

### 3.3 数据（D 类）
| # | 需求 | 验收标准 |
|---|---|---|
| D1 | **最小埋点集**（事件清单见下表） | 每事件真实触发且字段完整；上报通道可验证 |
| D2 | 埋点失败不影响游戏（try/catch 包裹） | 断网时游戏正常 |

**最小埋点事件清单**：`app_start / level_start / level_win / level_fail|exit / tool_use / ad_show / ad_click / ad_complete / ad_fill_fail / session_duration`（各带口径：时间戳、关卡号、步数、用时、场景名、错误类型等）。

### 3.4 合规（C 类）
| # | 需求 | 验收标准 |
|---|---|---|
| C1 | **隐私政策**页/入口（含广告 SDK 数据说明） | 上线材料含；游戏内有入口 |
| C2 | **广告标识合规**：广告按钮有明确"广告"标识 | 视觉审查 |
| C3 | **未成年人保护**：按平台要求 | 平台审核通过 |
| C4 | **无任何假功能**：假广告/假分享/虚假奖励 | 代码审查 0 处 |

## 4. 技术实施要求（发给 WorkBuddy 的硬约束）

1. 广告 SDK 引入：单文件 HTML 允许增加 `<script src="SDK">`（打破零依赖是商业必要）
2. **新增 AdService 分层**：Game → AdService → Test/TapTap Provider，环境一键切换
3. 存档用 `localStorage` + 简单校验（CRC/盐值），损坏时静默重建
4. 埋点上报：无后端先 `sendBeacon`/`fetch` 到自有收集 URL 或平台数据通道
5. 所有新功能必须过现有自动化测试；新增用例：广告 mock（成功/失败/超时）、存档读写/损坏恢复、埋点事件正确性、新手引导回归、**双环境切换**
6. **回滚验证**：每个新断言先故意改坏产品代码确认会 FAIL

## 6. 合规检查清单（复用核心：每个新项目都要过）

| 检查项 | 说明 | 状态 |
|---|---|---|
| 假按钮清理 | 任何"点了白拿奖励"的按钮，上架前必须替换或移除 | ☐ |
| 广告 SDK 正规性 | 只用平台官方/聚合正规 SDK | ☐ |
| 隐私政策 | 含广告 SDK 数据说明；儿童/未成年保护 | ☐ |
| 广告标识 | 广告按钮可辨识，不诱导误点 | ☐ |
| 版号/备案认知 | H5 免费无内购走平台备案/审核；开放内购/商业广告正式运营时资质升级，上架前查平台最新规则 | ☐ |
| 数据合规 | 埋点不采集敏感信息；用户标识匿名化 | ☐ |
| 崩溃与错误 | 线上错误有上报 | ☐ |

## 7. 反面教材（《解压水消除》踩过的坑，其他项目避免重蹈）

| 坑 | 后果 | 规避 |
|---|---|---|
| 广告触发=卡死，但游戏保证不卡死 | 广告触发≈0，收入恒 0 | 广告挂日常场景 |
| 无埋点 | 改什么都没法判断 | 埋点进 P0 |
| 无存档 | 刷新丢进度=惩罚回头客 | 存档是留存地基 |
| 单局 9 分钟 | 解压品类高流失 | 单局 ≤5 分钟进 KPI |
| 新手第一关接水断供无提示 | 新手第一个动作困惑 | 可喝性校验 + 断供提示 |
| "零依赖单文件"约束 | 回避一切商业依赖 | 商业功能允许打破约束 |

## 8. 当前项目应用（解压水消除 → 4 周执行计划）

| 周 | 交付 | 对应需求 |
|---|---|---|
| 第 1 周 | 埋点 D1 + 存档 K1 + 删假按钮 R4 | 数据/留存地基 |
| 第 2 周 | 新手教学 K2 + 可喝性校验 + 断供提示 | 留存/体验 |
| 第 3 周 | AdService 双环境 + TapTap 激励视频 SDK R1 + 广告场景 R2/R5 + 失败降级 R3 | 变现 |
| 第 4 周 | 星级 K4 + 每日挑战 K5 + 单局时长 K3 + 合规 C1~C4 | 留存/合规收口 |

**验收看两个数字**：广告日均曝光 > 100 次、次日留存 > 5%。看不到，回头查埋点与引导。
