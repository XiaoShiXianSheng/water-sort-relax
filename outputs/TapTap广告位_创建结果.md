### 为什么必须把 env 从 'test' 改成 'online'

**这是一次真实的「静默零收益」事故**：光把广告位 ID 填进去是**没用的** —— 只要 `CFG.env` 还是 `'test'`，
真机上跑的就是**模拟广告**（点一下直接发奖，根本不请求广告平台），一个广告费都收不到，
而且**不报任何错**，游戏照常玩，只有翻代码才看得出来。

改成 `'online'` 之后靠已有的自动降级逻辑保证安全，两个环境都不用改代码：

| 运行环境 | 结果 |
|---|---|
| 真机（TapTap 容器注入了 `tap`）+ 有 adUnitId | → `online`，真实拉广告 |
| 本地浏览器 / Node 测试环境（无 `tap`） | → 自动降级 `test`（原因 `no-tap-runtime`） |
| 有 `tap` 但 adUnitId 是空 | → 自动降级 `test`（原因 `no-ad-unit-id`） |

调试时仍可用 URL 强制切换：`?ad=online` / `?ad=test`。

### 2. 屏幕方向：创建时被建成「横屏」→ ✅ 已于 2026-09-29 全部改成竖屏

**问题**：新建推广位表单里「屏幕方向」默认选中**横屏**，创建时两次尝试改都没生效

它会吃掉所有点击 —— 之前"改了没反应"就是被它拦的）。
游戏是竖屏 720×1280，推广位却是横屏，激励视频/插屏可能以横屏素材呈现。

**修复结果（已回读服务端状态核验）**：

**怎么改成的（可复用）**：`agent-browser` 在这个环境里一执行 `open` 就会把宿主进程带走

## 四·补、本轮抓到的两个「隐形失守」（2026-09-29）

这两件事都属于**看起来一切正常、其实链路已经断了**，值得单独记下来。

### 1. `publish_taptap/index.html` 落后于主文件（上传包取件处）

- 现象：该文件里是 `env:'test'`、`adUnit:{rewarded:'',interstitial:''}` —— **没有广告位 ID**。
- 当时的实际情况：真正要上传的 zip 恰好是**对的**，所以没造成损失。
- 危险在哪：`publish_taptap/` 正是「重新打个包」的取件目录。谁要是重打一次包，
  就会把**没有广告位 ID 的旧版**打进上传包 → 真机跑真实广告却拿不到 adUnitId
  → **又一次静默零收益**（游戏照常玩，不报任何错）。
- 顺带发现 `outputs/` 里还躺着 4 个旧包（`tap_upload_v4.1.zip` / `_clean` / `_dir` / `_tar`），
  全是加广告前的版本，其中 `_tar` 解出来还是 `watersort/index.html`（多一层目录 = 上传必失败）。

**治本**：
- 门禁 G8a 从「只查 `publish_water/`」改成**查每一个发布副本**（现在 2 个目录都查）。
- 新增门禁 **G8c**：把 `outputs/` 里**每一个**含 `index.html` 的 zip 拆开比 md5
  —— 包内是 deflate 压过的，肉眼完全看不出版本，只能拆包验。
- 旧包已归档到 `outputs/_archive_旧版上传包/`，上传包重打成包含最新图标与说明的完整 3 件套。

> G8c 上线当场就抓到了 2 个旧包（md5 `516536f2…` ≠ 主文件 `282e711c…`），证明它不是空转。

### 2. 回滚验证脚本本身早已语法报错（验证器烂了没人知道）

- 现象：`node qa_rollback.js` 一跑就 `SyntaxError: Unexpected token '|'`。
- 根因：一段**块注释里嵌了内层块注释的收尾标记**，把外层注释提前闭合，
  后面半行 `| 'test'(模拟完成…)` 成了裸代码。
- 危险在哪：`qa_rollback.js` 是**独立运行**的（不在 `qa_run.js` 里），
  它死了没有任何地方会报警 —— 也就是说，那之后所有「回滚全绿」的说法**都是无效的**。

**治本**：
- 修掉注释；并在注释里写明「块注释里不要再出现斜杠星号 / 星号斜杠这对字符」。
- 新增门禁 **G10：QA 脚本自身语法自检** —— 对全部 11 个 `qa_` / `test_` 开头的脚本做纯语法编译。
  **验证器本身必须先被验证**；这类「测试基建悄悄烂掉」以后会当场变红。
- 写 G10 注释时又踩了同一个坑（把 `qa_` + 星号 + 斜杠 写成简写），也被立刻抓出来 —— 算是自证有效。

## 四·再补、应用图标改成「只有游戏标题」版（2026-09-29）

**需求原话**：「目前 logo 上文字可能有点多余，需要你再生成一个新的，只有我们的游戏标题即可」。

**改法（关键取舍：不用图像生成模型）**

原图标 = 蓝色渐变底 + 托盘/三色药丸/三玻璃瓶/水滴插画 + 大字「水消除」+ 小字「解压 · 排序」。
新图标 = **插画 1:1 不动**，只把下面两行文字擦掉，重绘成单行「解压水消除」。

- 为什么不用 AI 生图：图像模型画中文极易糊字/错字，而这是要见人的品牌资产；
  且重画插画会让风格漂移。所以走**像素级重绘**：确定性、零成本、插画零改动。
- 具体做法（已沉淀到技能 `cdp-chrome-automation/references/png-text-layer-redraw.md`）：
  1. 先采样确认背景是**纯垂直渐变且同一行内横向恒定** → 于是可以「逐行取左右边缘像素中位数」
     作为该行背景色，整行铺色，渐变无缝续接；
  2. 用「这一行相对左边缘的亮像素数」自动定位插画底边（y=367）与文字顶边（y=375），
     取 `TOP = 插画底边 + 2`（=369）作为擦除起点，保证既不伤插画、也不留残字；
  3. canvas 重绘单行标题，并**自检**：插画区逐像素与原图比对（要求 diff = 0）、
     擦除区不得残留非白亮像素、新文字不得出界。

**候选与选定**：做了 4 档（62px / 66px / 58px × 加粗与否），逐张肉眼比对后选
**62px + 2px 同色描边加粗** —— 笔画厚度与原「水消除」一致，左右留白各 101px，小尺寸下最清楚。

| 项 | 值 |
|---|---|
| 新图标 | `publish_taptap/icon_512.png`（512×512，76695 B，md5 `df4c1e2f…`） |
| 旧图标 | `publish_taptap/icon_512_old_双行版.png`（512×512，27086 B，留档） |
| 交付副本 | `outputs/logo_解压水消除_512.png` |
| 自检 | 插画区 diff = 0 / 残字 = 0 / 文字左右留白 101px、上 34px 下 45px |
