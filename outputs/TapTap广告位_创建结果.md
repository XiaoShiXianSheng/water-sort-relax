### 为什么必须把 env 从 'test' 改成 'online'

**这是一次真实的「静默零收益」事故**：光把广告位 ID 填进去是**没用的** —— 只要 `CFG.env` 还是 `'test'`，
真机上跑的就是**模拟广告**（点一下直接发奖，根本不请求广告平台），一个广告费都收不到，
而且**不报任何错**，游戏照常玩，只有翻代码才看得出来。

改成 `'online'` 之后靠已有的自动降级逻辑保证安全，两个环境都不用改代码：

| 运行环境 | 结果 |
|---|---|
| 真机（TapTap 容器注入了 `tap`）+ 有 adUnitId | → `online`，真实拉广告 |
| 本地浏览器 / Node 测试环境（无 `tap`） | → 自动降级 `test`（原因 `no-tap-runtime`） |
| 有 `tap` 但 adUnitId 是空 | → 自动降级 `test`（原因 `no-ad-unit-id`） |

调试时仍可用 URL 强制切换：`?ad=online` / `?ad=test`。

## 三、⚠️ 两个必须知道的坑

### 1. 这是「测试」推广位，不是正式的
平台顶部一直挂着提示：

> 「完成资质认证前，只能创建测试媒体。已有正式媒体的流量主请尽快完善资质信息，超过 40 天未认证将会影响结算。」

创建成功页明确写了**四步走**：
1. 接入 SDK
2. 测试联调
3. **把测试设备通过【测试工具】加入平台**（否则验收会被判定行为异常）
4. **将应用属性调成「正式」，并且把推广位属性也调成「正式」**

→ **也就是说：要真正开始赚钱，必须完成资质认证 + 把媒体/推广位属性切到「正式」。**
测试位只能用于开发联调。

### 2. 屏幕方向创建成了「横屏」
表单里「屏幕方向」默认选中**横屏**，创建时两次尝试改成竖屏都没生效（疑似：表单在选定所属媒体后会重置屏幕方向）。
**游戏是竖屏（720×1280），需要把这两个推广位改成竖屏**，否则激励视频/插屏可能以横屏呈现。

→ 待办（**手动 30 秒**）：进「推广位管理」编辑这两个推广位，把屏幕方向改为竖屏。
> 本轮想用浏览器自动化直接改完，但**当前沙箱会直接掐断浏览器进程**（`agent-browser open` 一执行，进程就没了），
> 所以只能留成手动步骤。入口见第四节。

## 六、自动化操作备忘（给以后复用）

- 该平台**登录态不持久**：每次新开浏览器都要重新用 邮箱+密码 登录（无验证码、无滑块，可全自动）。
- 进「新建推广位」页会**必弹一个资质提示框**，要先关掉再操作。
- 页面元素的 ref 编号**每次 DOM 变化都会整体位移**，必须「每次点击前重新快照、重新取 ref」，不能跨步骤复用 ref。
- **本机沙箱当前跑不了浏览器**：`agent-browser open` 会让整个 shell 进程消失（不是报错，是直接没了）。
  判断办法：`agent-browser --version` 能打印 `0.27.0`，但一执行 `open` 会话就断 → 不是装坏了，是沙箱不让起 Chromium。
  需要真实浏览器操作时，让用户在自己电脑上点，或申请非沙箱执行。
