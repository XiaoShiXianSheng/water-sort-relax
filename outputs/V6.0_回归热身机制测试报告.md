## 1. 这条规则要解决什么问题

玩家打到第 15 关，隔了几天再打开，最怕两件事：

1. **进度倒退** —— 「上次明明到 15 关，怎么又让我从 14 关/第 1 关开始？」
2. **手生了还硬上强度** —— 关还是第 15 关，但一上来就是峰值难度，连输两把就卸载。

V6.0 的解法是把**两件事拆成两个独立的量**：

| 概念 | 存哪儿 | 变不变 |
|---|---|---|
| **最高关卡 / 解锁进度**（`level` / `maxLevel`） | `Store` 存档 | **只增不减**，热身机制一个字节都不碰 |
| **本次挑战的难度档位**（`warmTier`） | `Store.data` | 回归后从「热身1」起步，赢了逐档回升 |

也就是说：**关还是那一关，但这一局先用更轻的盘让你找回手感。**
热身打完（回到 0 = 正常档）即自动收尾，玩家全程无感、不需要任何设置。

## 2. 配置参数（全部可配，不写死）

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `returnWarmupEnabled` | `true` | 总开关；关掉后行为与 V4.0 **完全一致**（向后兼容的退路） |
| `returnWarmupInactivityThreshold` | `12*3600`（12 小时） | 多久没打开算「一段时间的回归用户」——「一段时间」是**参数化**的，不是硬编码 |
| `returnWarmupStartTier` | `-2` | 回归后本次挑战从哪一档起步（−2 = 热身1，比正常档低两档） |
| `returnWarmupRampStep` | `1` | 每次成功后难度回升几档（回到 0 = 正常档，热身结束） |

> 档位轴是**有正有负**的一条线：
> `-2 热身1` → `-1 热身2` → `0 普通（正常档）` → `1 困难` → `2 极限`
> 负档只缩棋盘（行/色/管/洞/冰一起降），正档只加约束、不动棋盘。

## 3. 状态机

```
                      空闲 ≥ 阈值 且 有历史进度
   ┌──────────┐   ────────────────────────────────▶   ┌──────────┐
   │  正常档   │                                       │  热身1    │
   │ warmTier │  ◀──── 通关（warmTier += RampStep）─── │ warmTier │
   │    0     │                                       │   -2     │
   └──────────┘                                       └────┬─────┘
          ▲                                                │ 通关
          │                                          ┌─────▼─────┐
          └────────── 通关（−1 → 0，热身收尾）────────│  热身2     │
                                                     │ warmTier  │
                                                     │    -1     │
                                                     └───────────┘
```

关键约束（都有断言守着）：

- **换关即失效**：热身绑在 `warmLevel` 上，玩家推进到下一关后 `resolveChallengeTier(lv)` 直接返回 0，
  不会出现「都打到第 20 关了还在热身」。
- **中途退出不重置**：`warmupOnBoot()` 对**已在热身中的会话**直接跳过 ——
  否则每天回来都被打回最低档，热身永远走不完。
- **热身通关只记「普通」星位**：热身不是刷星捷径，不会解锁困难/极限。
- **显式档位 / 每日挑战优先**：玩家自己在结算页选了「困难」，或跑每日挑战（固定种子）时，热身不参与。

## 4. 存档字段（`SAVE_VER = 2`）

```js
maxLevel:1,      // 最高关卡：到达过的最高关，只增不减
lastPlayed:0,    // 最近游玩时间（epoch 毫秒）；改存档任何东西都会刷新它
warmActive:0,    // 本次会话是否处于「回归热身」
warmTier:0,      // 本次挑战难度档位（<0 = 热身档；0 = 正常档）
warmLevel:1,     // 热身绑定在哪一关（换关即失效，防蹭热身）
warmWins:0       // 热身里连续成功次数（逐档回升的观测 / 埋点）
```

`migrate()` 对每个字段做**类型 + 区间**双重兜底：非数字/非有限值 → 回落到默认值；
`warmTier > 0` → 强制拉回 0（正档是玩家自己选的挑战档，不属于热身）；
`maxLevel < level` → 抬高到 `level`。v1 老档能平滑迁移。

## 5. 14 条验收断言（逐条对应用户要求）

| # | 断言 | 对应的用户要求 |
|---|---|---|
| ① | 首次进入正常递进：连打 1~15 关全程都是普通档（不会被误判为「回归用户」） | 新玩家不被误伤 |
| ② | 连续游玩不触发回归热身（第 5/10/15 关，连判 3 次都不触发） | **要求②：连续游玩不触发热身** |
| ③ | 长时间未玩后回来：仍停在第 5/10/15 关，进度与星/档位解锁/道具/每日挑战**全部无损** | **要求③：回归后仍停在原关卡；要求⑧：不丢进度** |
| ④ | 回归后本次挑战从「热身1」（最低档）开始，且这一局生成的确实是更轻的盘 | **要求④：从容易的热身档起步** |
| ④-补 | 热身盘在「密度/颜色/水管/格数/门洞/冰冻」六项上**全维度 ≤** 正常盘，且**仍然可解** | 热身必须真的更轻、且不能变成死局 |
| ⑤ | 连续成功后逐档提高：热身1 → 热身2 → 普通，两连胜后热身自动收尾 | **要求⑤：连续成功按档提升** |
| ⑥ | 中途退出再回来：热身档位**不被重置**（继续从热身2 打起）、进度与星完全一致 | **要求⑥：中途退出重进状态正确** |
| ⑦ | localStorage 保存 `maxLevel` / `lastPlayed` / `warmTier`（v1 老档能迁移、脏字段被修正、校验和有效） | **要求⑦：localStorage 保存三字段** |
| ⑧ | 不丢失玩家进度：热身全过程 `level` / `maxLevel` / 星 / 档位解锁 / 道具 / 每日挑战**零改动** | **要求⑧：不丢进度（正面 + 反面双查）** |
| ⑨ | 四个配置参数真的生效（总开关 / 阈值 / 起始档 / 回升步长），且新玩家永不被误判为回归 | 「一段时间没玩」必须**参数化** |
| ⑩ | 热身严格绑定在「当前这一关」：换关即失效，且全程不写 `level` / `maxLevel` | 防蹭热身 / 防进度被热身写脏 |
| ⑪ | 热身通关只记「普通」星位，不解锁困难/极限 | 热身不是刷星捷径 |
| ⑫ | 显式指定档位 / 每日挑战固定种子时，热身不参与 | 热身只作用于「打开游戏默认进的那一关」 |
| ⑬ | 档位标签可读：−2 / −1 显示为「热身1」「热身2」，0/1/2 走原挑战档名 | UI 不出现「档位 −2」这种天书 |

### 断言写法上的两个细节（防假绿）

- **改坏采样点**：涉及「阈值类不变量」的采样必须放在 `genLevel()` **之后**、`frames()` **之前**。
  本项目历史上踩过：冰冻不变量在 `frames()` 之后采样，主循环第一帧就把不合格的冰冻瓶化开，永远查不到。
- **两种「进度一致」分开写**：
  - `progressEqual()`（**精确相等**）—— 用于「这一局没打完」的路径（③、⑥）；
  - `progressNotLost()`（**不倒退**）—— 用于「确实通关了」的路径（⑤、⑧）。
  第一版把两者混用一个「精确相等」，结果 ⑤/⑧ 因为「通关本来就该多一颗星」而假 FAIL。
  **测试自己会把状态改对，断言不能要求它没变。**

## 6. 反假绿：回滚验证

`qa_rollback.js` 里有专门针对热身的改坏用例（改坏产品代码 → 断言必须 FAIL → md5 校验还原）：

| 改坏内容 | 必须 FAIL 的断言 |
|---|---|
| `genLevel` 档位解析坏掉（永远困难档） | `test_water.js` 冒烟后的档位哨兵 |
| 极端档 `tier>=2` 整段短路（极限 == 困难） | 三档挑战真的更难 |

> ⚠ 本轮修 `qa_rollback.js` 时发现一个**工具自身的坑**（已在工具里根治）：
> 上一次回滚被 `SIGTERM` 打断，产品文件留在「已改坏」状态；下一次运行把它当成 original 快照，
> 于是 24 条用例 `find` 全部命中 0 次、md5 校验却「通过」——整套回滚静默失效。
> 现在加了两道护栏：① 开跑前自检任何目标文件是否残留 `rollback-test` 标记，有就拒绝启动（退出码 2）；
> ② 打补丁前登记 `inFlight`，`SIGINT/SIGTERM/SIGHUP` 回调里先还原再退出。
