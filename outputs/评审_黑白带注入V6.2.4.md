## 1. 本次改了什么（V6.2.4）

**颜色辨识度优化（纯视觉层改动，不改变关卡结构/可解性）：**

| 项 | 改动前 | 改动后（V6.2.4） |
|---|---|---|
| 黑 `#2b2b33` | L37（14色关）才首现 | **L10 起每关必在** |
| 白 `#ffffff` | L45（15色关）才首现 | **L10 起每关必在** |
| 低关 L1–9 | 取调色板前 C 个 | 不变（新手用易分辨基础色） |
| 灰 `#7f8c99` | — | **本次不提前**（用户拍板「灰色先不着急」） |

实现方式：新增 `pickColorSet(C, lv)`——`lv>=10` 时颜色集固定以 `[黑,白]` 打头、其余从调色板前段补足；`lv<10` 维持原 `0..C-1` 顺序。仅替换了瓶子着色时的索引来源，**瓶子数、格数、门洞、冰冻、台面槽全部不变** → 可解性与方案B完全一致。

## 2. 难度体系（方案B，已门禁 + bot 双验证）

**难度开关：`有效空槽 − 颜色数`（eff）**
- 颜色数 `C ≥ 7` → eff = −3（台面槽比颜色少 3，最紧）
- 颜色数 `C < 7` → eff = −1（新手宽松）
- 三档（普通/困难/极限）统一压在 `eff ≥ −3` 地板；**−4 才是真必输区**（受控实验实测）。

**设计门禁 `qa_design.js --gate`：72 PASS / 0 FAIL**（本次注入后重跑，全绿）。
**三档「有效空槽 − 颜色数」分布实测：**
- 普通：`−3:81 关 / −1:5 / 0:3 / +1:1`
- 困难：`−3:81 / −2:3 / −1:2 / 0:3 / +1:1`
- 极限：同困难（高关三档收敛于 −3 地板，属正常）

**真实 bot 全量复核（90 关 × 3 档，固定种子、带道具/复活/重开，注入仅换视觉色、结构不变）：**
- 困难档（T1）：**90/90 全部通关**，总尝试 91，复活 0，重开 0（仅 L49 用 2 次尝试，仍清）。
- 极限档（T2）：**90/90 全部通关**，总尝试 94，复活 0，重开 0。
- 普通档（T0）：**90/90 全部通关**，总尝试 92，复活 0，重开 0。
- 结论：三档均 0 复活 0 重开、全部可解，**不存在必输关 / 不卡死**成立。

**颜色数 / 总槽 / 开放槽 / eff 对照（代表关）：**
| 关卡 | 颜色数 | 总槽 | 开放槽 | eff |
|---|---|---|---|---|

| L10–11 | 7 | 5 | 4 | **−3（首现黑+白）** |

## 3. 已知待优化（用户已反馈，未阻塞本次上线）

1. **部分低关仍偏松**：L1–9 的 eff=−1（首战通关率约 40~50%、个别关 85%+），用户体感「有些地方还是太简单」。
   → 规划：上线后把低关 eff 从 −1 收到 −2（仍 > 真必输线 −4），或另开难度旋钮。
2. **高关三档区分度饱和**：门洞/冰冻已顶到 GATE_CAP/ICE_CAP、槽位也压到 −3 地板 → 困难/极限档与普通档难度完全相同（密度 188.5/188.5/188.5）。
   → 规划：若要高关挑战档有区分度，需另开旋钮（挑战档减道具/撤销额度）或抬 GATE_CAP/ICE_CAP；当前未做，用户已知情。
3. **变现现状**：广告触发条件（卡死）与卖点（保证不卡死）互相抵消 → 广告触发≈0；无用户标识/排行榜/体力 → 留存钩子弱。网页版零收益（广告位属性随媒体走，需游戏先上架 TapTap 容器）。
