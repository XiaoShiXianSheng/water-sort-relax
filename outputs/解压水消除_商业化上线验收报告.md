## 1. 本次实际修改清单

全部产品改动集中在 `outputs/解压水消除.html`（单文件约 134KB，零依赖，ES5）。

### 1.1 广告与商业化

- [x] **AdService 三层抽象**：`Game → AdService → TestAdProvider / TapTapAdProvider`。TEST 模式完整保留（模拟完成、不产生真实收入），未被 Online 接入删除。
- [x] **Online 接入只用 TapTap 小游戏官方 API**：`tap.createRewardedVideoAd({adUnitId})` / `tap.createInterstitialAd({adUnitId})`，`onClose(res.isEnded)` 为 true 才发奖。**未引入任何未经确认的第三方 SDK**（没有内嵌 Dirichlet/TapADN 的 SDK 脚本，没有 `window.tt` 之类臆测接口）。
- [x] **安全阀**：`CFG.adUnit` 为空（尚未在开发者中心开通广告）时自动降级回 TEST（`degradeReason='no-ad-unit-id'`），游戏流程绝不会被广告卡死。
- [x] **广告幂等**：同一 token 的重复 `onClose` 只发 1 次奖（连按 3 次也只发 1 次，`reward_duplicate_blocked`）。
- [x] **广告频控全部配置化**（`CFG`）：`rewardedSessionCap=3`、`interstitialSessionCap=1`、`interstitialCooldown=300s`、`interstitialAfterWins=3`、每关复活上限 1 次。
- [x] **广告失败降级可配**：`adFailFallback='free'`（放行）/`'none'`（只提示）；SDK 缺失/抛异常 → 降级放行而不是卡住。
- [x] **低频插屏**：连续通关 3 次 + 冷却 300s + 单会话 1 次，三个开关全过才展示。
- [x] **工具补充广告**：工具条「补 1 次」接 `AdService.show('tool_*')`；补完**不自动进入模式**（需再点一次，防误触）。
- [x] **删除假分享奖励**：`shareInvite / shareHelp / unlockSlotViaAd` 全部删除；V4.0 只保留 3 个广告场景（失败复活 / 工具补充 / 胜利后低频插屏）。

### 1.2 失败与复活（P0 硬要求）

- [x] **真实失败机制** `enterFail(reason)`：撤销次数用尽 + 工具用尽 + 无合法决策时才判负，不靠"卡死"假失败。
- [x] **复活后必须恢复可玩状态（V4.0 §11）**：`rescueGrant()` 四级兜底（开槽 → 恢复安全快照 → 发工具 → **补 1 次「随心互换」**），`doRevive()` 用 `while(!hasLegalDecision() && guard++<6)` 循环保证——**复活后必然存在至少一个合法决策**。
- [x] 修复「解锁后撤销会吃掉免费解锁次数」：`snapshot()` 序列化 `unlockLeft`，撤销时一并回滚。

### 1.3 存档 / 埋点 / 难度 / 引导

- [x] **localStorage 存档**：djb2 校验和 + 版本号 + 脏档重建 + 老档迁移 + 隐私模式静默降级（`save()` 返回 false 不抛异常）。
- [x] **埋点 `Track`**：本地缓冲 + `sendBeacon`，兜底 `new Image().src`。**为满足"零外部依赖"架构红线，去掉了 `fetch` 兜底**（同时避开 CORS 预检）。`trackUrl` 留空 = 只写本地缓冲，离线可核对。
- [x] **难度重做**：格子硬上限 **26**、瓶数硬上限 30；1~3 关教学（9 格/3 色/无门洞/开局 100% 可点）；4~8 关每次只引入一个复杂度（第 6 关门洞、第 7 关冰冻）；9 关以后靠**决策密度**递进，不再堆棋盘。
- [x] **星级**：`par = max(10, round(瓶数×1.4 + 门洞×2))`，按普通/困难/极限分别记。
- [x] **普通/困难/极限**：同关三档槽位递减、密度递增、门洞不减；通关普通解锁困难，通关困难解锁极限。
- [x] **每日挑战**：日期派生种子，同一天所有人同一关。
- [x] **首页动效**：漂浮瓶 + 水柱 + 星级进度 + 两个点击理由。
- [x] **新手引导**：1~3 关提示条。
