## 3. 缺的：三件只有你能做的事

### 3.1 TapTap 账号授权（CLI 登录）· 1 分钟

我发起了 `taptap-cli auth login`，它给出设备授权链接：

```
https://accounts.taptap.cn/device?qrcode=1&user_code=<每次不同>
```

同一条链接我可以用 `taptap-cli auth qrcode <url> -o 二维码.png --size 512` 转成
**二维码图片**直接给你扫，手机端点开更省事。

我试着用已登录的 Chrome profile 直接打开 —— **跳到了手机号登录页**
（`accounts.taptap.cn/login`，要收验证码），这一步我做不了，只能你在浏览器里登一次。

**你做**：扫二维码（或打开链接）→ 登录 → 点确认。完成后 CLI 本地会存凭据，后面的
建游戏、传包、提审**我都能继续自动跑**。

⚠️ **两个已踩过的坑，别再犯：**

1. **device code 只有约 5 分钟有效**（CLI 等到点就报 `token_expired`），
   我这边是后台挂着等的，超时就只能重新生成一个——**码会变，旧的别点**。
2. **不要同时发起两个 `auth login`**：它们共用一份待授权状态，会互相冲掉，
   两个都失败。一次只跑一个。

已经失败过的码（作废，仅作记录）：`twbxx` / `45ttg` / `awlxg` / `eyg2a`。

### 3.2 开发者入驻 + 实名认证 · 后台点几下

TapTap 开发者分「注册开发者」和「认证开发者」。个人主体能走，
但需要**先有一个完成实名认证的 TapTap 账号**，再在开发者中心走入驻流程。
这一步同样要你本人（实名）。

### 3.3 隐私政策 / 用户协议里的 2 个占位符 · 回我两个字就行

`outputs/legal/privacy.html` 和 `terms.html` 各出现 2 次，共 4 处：

```
【开发者名称】   ← 个人主体就写真名（和 Dirichlet 后台主体一致：个人 / 石长建）
【联系邮箱】     ← 我编不了，你给我一个
```

**你把这两个值回给我，我一条命令填完**（已经写好的 `fill_legal.js`）：

```bash
DEV_NAME="石长建" DEV_MAIL="you@example.com" node fill_legal.js
```

它会：替换 4 处占位符 → 同步到 `publish_water/` → 自动重打 `tap_upload_v6.2.zip`，
并在结尾报告**剩余未填占位符数量**（不是 0 就不重打包，避免把带占位符的包传上去）。
隐私政策 URL 不变，不需要重发游戏本体（法务文档不在主文件里）。

## 4. 合规：一个必须提前接受的现实

TapTap 官方《开发者快速入门指南》的资质表（原文摘录）：

| 游戏性质 | 需要提交的资质 | 上线形式 |
|---|---|---|
| 联网 + 有内购 | 版号 / 软著 / ICP 备案 / 防沉迷 / 隐私合规 | 正式上线 |
| **联网 + 无内购** | **ICP 备案 / 防沉迷 / 隐私合规** | **开放试玩** |
| 不联网 + 无内购 | 防沉迷 / 隐私合规 | 开放试玩 |

> 「正式上线」开放下载或开放内购，**必须提供游戏出版物号（ISBN）**；
> 没有版号只能以「开放试玩」形式上架。

**我们的定位**：单机可玩、无内购、但广告要联网 → 归到「**联网 + 无内购**」
→ 能拿到的上架形式是 **「开放试玩」**，**不是「正式上线」**。

- **版号基本堵死**：个人主体不能申报（需内资游戏企业主体），周期 8~12 个月。
  想走「正式上线」= 先注册公司 + 办软著 + 申报版号，是另一条长线。
- **软著**：官方规范要「原始取得」的登记号 + 证书扫描件。个人能办（几百元、1~2 个月）。
  按上表，我们这条线（联网+无内购，开放试玩）**不强制软著**。
- **ICP 备案**：联网这条线要 App 的 ICP 备案信息。H5 小游戏走平台容器，
  **到底算不算"需要独立 ICP 备案"、还是用平台资质覆盖 —— 必须问官方，我不猜**。

**❓ 最关键的一个未知（只能问官方）**：
「开放试玩」形态下**能不能接广告变现、有没有真实收益**。
这直接决定"上架换收益"这条路成不成立。建议带着这句话去问客服：
> "个人主体、无内购、联网（仅广告）的 H5 小游戏，以『开放试玩』形式上 TapTap，
> 是否可以接入激励视频/插屏广告并产生收益？收益结算需要哪些资质？"

## 5. 广告正式位：卡在同一道门上

上一轮诊断（`广告位正式化_实测诊断_V6.2.md`）已经查明：Dirichlet 后台建**正式**媒体时，
最后一项资质是「**选择 TapTap 上架的游戏/应用**」，下拉里只有另外两个测试游戏，
**没有「解压水消除」——因为游戏还没上架 TapTap。**

所以顺序是死的：

```
游戏上架 TapTap（拿到 game ID）
        ↓
Dirichlet 建「正式」媒体（选中这款游戏）
        ↓
建「正式」推广位 → 拿到正式 adUnitId
        ↓
回填 CFG.adUnit + 把 adUnitIsTest 改 false → 重新打包上传
        ↓
真机验证看到的是真广告
```

**在拿到 game ID 之前，广告位正式化这一步无法推进**（不是操作问题，是平台的依赖顺序）。

## 6. 授权之后，我会按这个顺序自动跑

| 步 | 命令 | 说明 |
|---|---|---|
| 1 | `taptap-cli developer +list` | 定位你的厂商 ID（dev-id） |
| 2 | `taptap-cli game:create` | 建游戏草稿（先 `--dry-run` 给你看参数，确认后 `--yes`） |
| 3 | `taptap-cli upload-h5-package` | 传 `tap_upload_v6.2.zip` |
| 4 | `taptap-cli upload <图>` | 传图标 + 5 张截图 + 封面/宣传图（自动进素材库） |

| 6 | `taptap-cli qualification:analyze` | **查资质缺口**（比我自己读文档准，是后台实时状态） |
| 7 | `taptap-cli app analyze-app-status` | 查还缺什么、能否提审 |
| 8 | `prepare-review-snapshot` → `precheck-app-review` | 提审前预检，看阻塞项 |
| 9 | `submit-app-review --yes` | **提审（不可逆，会等你最后确认一次）** |

> 第 9 步我会先给你看预检结果，你说"提"我再提。

1. **今天**：回我「开发者名称 + 联系邮箱」→ 我补齐隐私政策并重新发布

先拿玩家和口碑；广告收益能不能开，取决于官方对第 4 条那个问题的答复。
