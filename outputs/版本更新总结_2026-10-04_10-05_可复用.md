## 1. 商业化：广告接入选型与触发时机（可复用）

### 1.1 只用两种广告形式
| 用途 | 形式 | 触发点 |
|------|------|--------|
| 补道具次数 / 解锁额外槽位 / 失败复活 | **激励视频** | 玩家**主动点击**入口后拉起 |
| 通关后的低频打断 | **插屏** | 玩家**关闭过关结算弹窗后**自动弹出 |

> 经验：**每端每种形式只建 1 个正式广告位**，代码里一个 ID 对一个位，别散着建。

### 1.2 插屏的触发时机（V6.4.10 踩过的坑）
- ❌ 错误做法：通关瞬间（`state==='win'`）就弹插屏 → **直接盖在过关结算弹窗上**，玩家还没看清星级就被挡脸。
- ✅ 正确做法：把「关闭结算弹窗」的动作收敛到一个统一出口，插屏在那里弹：
  ```js
  function closeWinAndInterstitial(after){
    if(G.interPending){
      G.interPending=false;
      AdService.showInterstitial('level_complete',{ onDone:function(){ if(after)after(); } });
      return;
    }
    if(after)after();
  }
  // 结算弹窗的「下一关 / 回首页」都走它
  ```
- 配套要求：**插屏只有一个调用点**，且场景名固定，方便审计与断言。

### 1.3 道具额度的产品设计（V6.4.7 → V6.4.12 的三次反复）
- 结论：**起始额度 0/0/0 + 撤销 1**，四个按钮**全部保持彩色**，红色角标**如实显示次数（0 就显示 0）**；
  点 0 次数的道具 → **拉起激励视频，看完 +1 次**。
- 中间踩的坑：
  - 按钮画成灰色 + 半透明 → 玩家以为「键坏了/点不了」，**不去点**，等于把广告入口自我阉割。
  - 点了完全没反应 → 用户无法理解，广告也进不去。
  - **两次都被推翻**，最终定稿是「彩色 + 红角标 0 + 点了走广告」。
- 通用原则：**广告入口的视觉必须"看起来可点"，不要用灰色表达"没次数"**；次数用角标表达。

### 1.4 广告失败绝不白送（V6.4.7 的关键修复）
- ❌ 旧逻辑：广告拉取失败时 `fallback` 里直接发奖 → 玩家「点一下就得奖励、广告从不弹出」，
  看起来像 bug，实际是把收入通道自我阉割。
- ✅ 新逻辑：失败只提示、**不发奖**，并打埋点（`ad_unlock_denied` / `ad_tool_denied`）。
- 通用原则：**没看成广告 = 不给奖励**；失败给提示，不给补偿。

### 1.5 埋点必须带版本号
- `CFG.version` 曾写死成旧字符串，导致所有埋点上报的版本都是错的 → 出事无法区分线上跑的是哪版。
- **每次升版必须同步改这一行**（建议加一条断言守住）。

## 2. SSP（广告平台）正式化：从测试位到正式位（可复用）

### 2.1 概念层级（最容易搞错）
- **推广位（space）**：代码里 `adUnitId` 挂的就是它。
- **媒体（media）**：推广位的归属主体。**测试/正式由媒体决定**。
- ❌ 不要把代码里的广告位 ID 换成"媒体 ID"，换了就断流。

### 2.2 推广位属性
- 属性枚举：`SPACE_TYPE_TEST`（测试）/ `SPACE_TYPE_FORMAL`（正式）/ 建错时会出现 `SPACE_TYPE_UNKNOWN`。
- **测试位只有白名单设备能拉到广告 → 真机收益恒 0**，必须转正式。

### 2.3 转正式的前置条件（实测）
1. 流量主**实名/资质**已通过（个人主体：身份证正反面，状态 `STATUS_PASS`）。
2. 推广位必须补齐材料，否则转不了：
   - **推广位路径描述** `ad_path_desc`（用户从打开 App 到看到广告的完整路径）
   - **推广位触发规则** `ad_trigger_rule`
   - **广告场景截图** + **广告场景录屏**
   - 素材样式（16:9 / 9:16 图片与视频）
   - 插屏还需「多少秒后自动关闭」（范围 5~30）
3. 平台审核（转正式后进入 `STATUS_CHECKING`）。

### 2.4 平台接口（实测有效，**必须带 `Publisher` 头**）
| 动作 | 方法 + 路径 |
|------|-------------|
| 列推广位 | `GET /adn-ssp-be/space/v1/list?page_num=1&page_size=100` |
| 查详情 | `GET /adn-ssp-be/space/v1/info/{id}` |
| 改资料 | `PATCH /adn-ssp-be/space/v1/{id}` |
| 开关（**停用的等价手段**） | `PATCH /adn-ssp-be/space/v1/{id}/effective_status`，body `{"effective_status":"EFFECTIVE_STATUS_OFF"}` |
| 查资质 | `GET /adn-ssp-be/qualify/publisher/v1/get_publisher_qualify` |

必备请求头：`Publisher: <流量主ID>` + `Authorization: Bearer <JWT>`。

> ⚠️ **推广位「删除」根本不存在**：整个前端（主包 + 25 个分包）只有 `create/list/select/info/security_key`，
> 网页上也只有「数据/编辑」。**想"删掉"冗余位 → 正确动作是关开关（`EFFECTIVE_STATUS_OFF`）**。
>
> ⚠️ `ssp.tapapis.cn/ssp-be/...` 会返回「不再支持流量管理变更，请去 ssp.dirichlet.cn 操作」；
> 而 `ssp.dirichlet.cn/ssp-be/...` 直连被 nginx 405。→ **写操作只能从网页 UI 走**。

### 2.5 用无头浏览器操作后台（可复用套路）
1. 登录态存在浏览器 profile 的 `localStorage`，键名如 `ssp-jwt-token`，**值必须带 `Bearer ` 前缀**（裸 JWT 会 401）。
2. 注入姿势：`page.evaluateOnNewDocument(t => localStorage.setItem('ssp-jwt-token', t), 原始值)`。
3. 写操作的真实路径不在 `adn-ssp-be` 而在 `ssp-be`（如 `PATCH /ssp-be/space/v1/{id}`），
   而 UI 内部实际走的是 `adn-ssp-be` 系列 → **照抄 UI 的请求最省事**。

### 2.6 上传广告场景素材（先删后传，没有"替换"）
- 上传区标签：**媒体推广位截图**（≥1280×720，推荐 1920×1080，≤20MB，jpg/png）/
  **媒体推广位录屏**（≤1000MB，mp4）。
- ⚠️「推广位示意图」只是**示例轮播图**，不是上传区，别搞错。
- ⚠️ 已有文件时**只显示删除图标，没有替换按钮** → **必须先删再传**。
- ⚠️ **删除图标用鼠标点不到**（被悬停层挡住）→ 必须用 JS 直接触发：
  ```js
  el.dispatchEvent(new MouseEvent('mouseenter',{bubbles:true}));
  el.click();
  ```
- 删除后块内会出现 `input[type=file]` → `elementHandle.uploadFile(绝对路径)`。
- ⚠️ `.upload-error-tooltip` 是**常驻元素**，别拿它判断上传失败（会假报错）。
- 成功标志：`edit?id=x` → 提交后 URL 跳回 `.../flow/promotion`。

## 3. TapTap 上架：可复制的提审链路（可复用）

### 3.1 「已上线」但玩家仍看到「敬请期待」
- 开关不在 `status=online`，而在 **`platform-status`**：
  | 字段 | 敬请期待 | 提供游玩 |
  |------|---------|---------|
  | `region_flag_android` | `1` | **`4`** |
  | `region_flag_ios` | `1` | **`0`**（枚举与安卓不同） |

### 3.2 标准提审链（照抄）
```
1) list-app-versions            看有没有 draft / reviewing
2) （reviewing 时）withdraw-app-review
3) create-draft                 带稳定 idempotency-key
4) list-app-versions            回读验证草稿真的建出来了
5) upload-h5-package <zip>      拿到 package id
6) list-packages                读出 main 槽的 expected
7) select-package               ★ expected 必须原样回填
8) save-changes                 补必填（如 author_name）
9) prepare-review-snapshot      期望 ready
10) precheck-app-review         期望 preaudit_passed=true、blockers=[]
11) submit-app-review --yes
```

### 3.3 三条硬经验
- ★ **`select-package` 的 `expected` 必须 `list-packages` 回读后原样回填**。
  草稿基于线上版本建出来时，main 槽 expected 是 `{h5_version_id:"<线上包>", kind:"h5"}`（继承线上），
  自己写 `{kind:"none"}` 会 409 conflict。
- ★ **判据优先级**：`list-app-versions` 有没有 `status=draft` >
  `get-app-version` 的 logs（review_submitted / approved / published）> 包 `is_releasing`。
  **没有草稿时，`get-app-module` 返回的 `revision=0` + 全 `filled=false` 是假象**，
  此时分析出来的「必填缺失 / 缺截图」全都是假信号。
- ★ **绝不需要 `reset-draft`**（高风险不可逆）。`create-draft` 本身没问题，
  以前"以为失败"是因为建完没回读验证。
- ⚠️ **无版号（个人主体办不到 ISBN）也能上架**：走「开放试玩」通道，资质 8 项全 `pending_upload`
  **并不阻塞提审**（`precheck` 零 blockers 已验证）。资质真正卡的是**广告结算**，不是上架。
- ⚠️ **自测二维码**（`test-qr-code`）是绕开审核/绑包卡点的唯一通道，真容器真机可直接验收。

## 4. 移动端适配：刘海 / 底部横条（可复用四条硬规则）

固定设计分辨率 + letterbox 的 Canvas 游戏，在 iPhone 上会出现顶底黑条。四条缺一不可：

1. `viewport-fit=cover`
2. CSS 变量承接 safe-area：
   ```css
   html{ --sat:env(safe-area-inset-top,0px); --sab:env(safe-area-inset-bottom,0px);
         --sal:env(safe-area-inset-left,0px); --sar:env(safe-area-inset-right,0px); }
   ```
3. JS 读取（宿主不支持则全 0），在**安全区内**计算 scale / offX / offY
4. `render` 开头**先铺满全屏底色**（`fillRect`），再画游戏内容 ——
   否则 letterbox 区域会露出透明/黑块

## 5. 自测体系：让 AI 自己跑完设计→开发→测试（可复用）

### 5.1 分层断言
| 套件 | 管什么 |
|------|--------|
| `qa_gate` | 上线门禁：体积、ES5 合规、无外部依赖、运行期兼容、广告位 ID 已填、副本/线上/包三方字节一致 |
| `qa_design` | 数值与设计不变量（水量守恒、不触顶、开局额度固定等） |
| `qa_biz` | 商业化链路（广告频控、只 1 个调用点、场景名集合、失败不白送） |
| `qa_ui` | 端到端点击链路（模拟真实点击坐标） |
| `qa_arch` | 架构约束 |

### 5.2 三条铁律
1. ★ **新断言必须能"反证"**：把修复撤掉 → 断言必须转红。只绿不红的断言等于没有。
2. ★ **旧守卫会守着被推翻的行为**：产品语义变了，必须同步摘掉/改写旧断言，
   否则会长期"假红"，把真回归淹掉。
3. ★ **改动主文件后，三方必须字节一致**：主文件 = 各发布目录副本 = 上传包内文件。
   门禁会拆包比 md5；旧上传包必须归档，否则门禁红。

## 6. 素材制作：截图 / 录屏也能自动化（可复用）

- **截图**：无头浏览器 + 按设计坐标点击，然后用图像库叠加**红框（广告展示区域）+ 文字（触发时机）**。
- **录屏**：连续 `page.screenshot()` 抓帧 → ffmpeg 合成 mp4。
  - ⚠️ 用 node 的 `execFileSync` 调 ffmpeg 在受限沙箱里会 `EBUSY`，**要从 shell 直接调**。
  - 帧率按「实际抓到的帧数 ÷ 实际耗时」设置，视频时长才和真实一致。
- **不用真解谜也能到"通关结算"**：直接调用游戏内的结算函数（如 `levelDone()`）即可复现画面。
- 平台规格：截图 1920×1080（竖版游戏画面居中贴底色即可）、录屏 mp4。

## 8. 一句话总结（给下一个游戏）

> **广告要真的赚钱，80% 的功夫在"位"和"时机"，不在代码**：
> 正式媒体 + 正式属性的推广位、额度 0 逼看广告、失败绝不白送、
> 插屏放在"结算关闭后"、按钮永远看起来可点。
> 剩下 20% 是把上架链路（draft → 绑包 → 快照 → precheck → 提审）跑成一条可重复执行的命令。
